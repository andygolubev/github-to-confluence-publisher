# Proposal: Page Identification via Hidden Metadata & SSL Fix with Docker

## Problem

Two weaknesses in the current publisher need to be addressed:

1. **Page identification is fragile.** Autogenerated pages are found by appending a visible text pattern (`(this page is autogenerated)`) to every page title and then searching via CQL `text~{pattern}`. This pollutes titles, is visible to readers, and can match unrelated pages if someone types the same phrase elsewhere.

2. **SSL verification is disabled.** Every `requests` call uses `verify=False` and urllib3 warnings are suppressed. This silently accepts any certificate, exposing the connection to MITM attacks.

A secondary concern is the hardcoded banner HTML with a generic "My project" GitHub link that is not configurable.

## Proposed Changes

### A. Hidden-metadata page identification

Replace the visible title-suffix pattern with **Confluence page properties** — a structured key/value store attached to each page that is invisible in normal page view but queryable via CQL.

- On **create**: attach a page property (e.g. key `autogenerated-by`, value containing a publisher identifier and optional run metadata) to each created page. Remove the search-pattern suffix from the title.
- On **search**: use CQL `page.property[autogenerated-by].value` (or content property endpoint) to find pages owned by this publisher, scoped to the configured space and parent.
- On **delete**: no change; pages are still deleted by id.

Benefits: titles stay clean, identification is machine-only, no risk of false-positive matches from human-edited pages.

### B. Proper SSL verification via Docker

Package the publisher as a Docker container that:

- Bundles the required CA certificates (system trust store plus any custom corporate certs mounted at build or run time).
- Removes all `verify=False` from `requests` calls so TLS is fully verified.
- Accepts all runtime inputs (Confluence URL, space, parent page id, credentials, GitHub token, source paths) as environment variables or mounted volumes, making it usable in CI (GitHub Actions), local runs, and other orchestrators.

### C. Configurable banner

Make the autogenerated banner content configurable (repository URL, project name) via config or environment variables instead of hardcoded HTML.

## Non-goals

- Incremental diff / partial update (still full-refresh model).
- Support for Confluence Data Center on-prem (Cloud REST API only for now).
- Changing the Markdown-to-HTML conversion pipeline.
