# Content properties and cleanup

Older versions of this publisher located autogenerated pages with a **text search pattern** in page body. Current behavior uses **Confluence content properties**: invisible metadata attached to each created page and queryable with **CQL**.

## Why properties

| Goal | How properties help |
|------|------------------------|
| Find “our” pages | CQL filters on `content.property[key].value` |
| Keep titles clean | No need for `(autogenerated)` suffix in the title |
| Avoid false positives | Unlikely to match arbitrary human-written pages |

## What gets stored

After each page is created, the publisher **POST**s a property (key from `publisher_property_key`) whose JSON value includes at least:

```json
{"publisher": "github-confluence-publisher"}
```

## Reader vs automation view

![Content property used for CQL and safe delete](/data_images/content-property-tagging.svg)

Readers see normal titles and HTML body. Automation uses the property to **list** pages to delete on the next full refresh.

## Migration note

If upgraded from a release that only used `confluence_search_pattern`, the implementation may still perform a **fallback** text-based search once to delete legacy pages, then recreate them with property tagging. See `openspec/architecture.md` for details.
