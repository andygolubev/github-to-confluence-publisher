# Content properties, search, and cleanup

The publisher marks every generated page with a content property so it can find its own pages later without putting visible machine tags in page titles.

![Property filtering, legacy fallback, and stale cleanup](/data_images/property-search-cleanup.svg)

## Property payload

The property key comes from `publisher_property_key` and defaults to `autogenerated-publisher`. The value is currently:

```json
{"publisher": "github-confluence-publisher"}
```

`set_page_property()` treats HTTP `409 Conflict` as harmless, which makes repeated upserts safe.

## Search strategy

The code does not rely on property-based CQL filters because they have been unreliable in Confluence Cloud. Instead it:

1. runs a descendant search beneath the configured ancestor
2. checks each returned page for the configured property key
3. keeps only pages that actually have the property

## Cleanup strategy

The deletion phase happens after publishing:

```text
stale_pages = existing_pages - published_pages
```

This keeps updated pages in place and removes only ids that belonged to an earlier publish snapshot but were not recreated or updated in the current run.

## Scope warning

The property filter protects unrelated manual pages during stale cleanup, but the upsert path is still title-based. A manually created page with the same title under the same parent can be updated by accident even if it does not have the publisher property. A dedicated parent page is the safest operating model.
